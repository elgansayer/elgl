# Hourly UI Primitive Parity Check

## Objective
Ensure all new UI development strictly utilizes the design primitives rather than ad-hoc Tailwind combinations.

## Instructions
1. Audit any new HTML added to the frontend.
2. Check for manual button, input, or card implementations (e.g., standard Tailwind web forms).
3. Refactor these elements to use the project's shared primitives (`app-button-primary`, `app-card`, `app-chip`, etc.).
4. Verify that the UI strictly adheres to the original HelloTalk screenshots (dark mode, neon accents).
