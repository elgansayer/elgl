# Repo Factory Dashboard

A lightweight self-hosted status dashboard for both repository-scoped Factory
instances, accessible at `factory.elgansayer.com` via the existing Cloudflare
tunnel.

## What it shows

- **Factory status** - running/paused, PID, uptime, hostname
- **AI provider health** - claude, codex, google, opencode, pi with circuit-breaker states
- **Active jobs** - which GitHub issues are being worked on right now
- **Backlog** - next 10 queued tasks with priorities
- **Disk usage** - root and factory state volume with usage bars
- **GitHub Actions** - last 20 workflow runs with live status
- **Pull Requests** - all open PRs with factory-reviewed labels highlighted
- **Recent commits** - last 10 commits to main

The dashboard auto-refreshes every 30 seconds with a progress bar indicator.
The HelloTalk Clone and Workout Agent tabs query isolated Factory state and the
matching GitHub repository.

## Quick start

```bash
# 1. Copy and fill in your secrets
cp .env.example .env
nano .env

# 2. Start
chmod +x start.sh && ./start.sh
```

The dashboard listens on `http://127.0.0.1:3100` (localhost only).

## Environment variables

| Variable | Required | Default | Description |
|---|---|---|---|
| `GH_TOKEN` | Yes | - | GitHub PAT (needs `repo` + `actions:read` scopes) |
| `DASHBOARD_USER` | No | `admin` | Basic auth username |
| `DASHBOARD_PASSWORD` | Yes | - | Basic auth password - must be non-placeholder and at least 16 characters |

## Cloudflare tunnel setup

1. Create a tunnel (skip if you already have one):
   ```bash
   cloudflared tunnel create factory-dashboard
   ```

2. Add this ingress rule to your tunnel config (`~/.cloudflared/config.yml`):
   ```yaml
   ingress:
     - hostname: factory.elgansayer.com
       service: http://localhost:3100
     - service: http_status:404
   ```

3. Add a CNAME DNS record in Cloudflare:
   ```
   factory.elgansayer.com -> <tunnel-id>.cfargotunnel.com
   ```
   Or via CLI: `cloudflared tunnel route dns factory-dashboard factory.elgansayer.com`

4. Start the tunnel:
   ```bash
   cloudflared tunnel run factory-dashboard
   ```

See `cloudflare-tunnel.example.yml` for a full example config.

## Project configuration

The container has explicit, read-only configuration for both projects:

- `HELLOTALK_STATE_DIR` and `HELLOTALK_GH_REPO`
- `WORKOUT_AGENT_STATE_DIR` and `WORKOUT_AGENT_GH_REPO`

Tabs are generated by `/api/projects`; every Factory and GitHub request is
scoped by a validated project slug. Add future projects to `src/projects.js`,
mount their state read-only, test, then rebuild the container.

## Technology

- **Zero npm dependencies** - pure Node.js 22 built-ins (`http`, `fs`, `path`)
- **Single Docker container** - Alpine-based, ~50 MB image
- **Read-only Factory mounts** - each repository state directory is mounted `:ro`
- **HTTP Basic Auth** - enforced at the server layer on all routes except `/health`
