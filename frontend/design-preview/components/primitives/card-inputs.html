Card & Inputs

card, input, textarea and select - four real components under src/app/components/primitives/. Classes below are copied verbatim from each component's hostClasses() / *Classes() computed signal.

Card

app-card - variant: default / elevated / outlined / interactive (renders role="button" and is keyboard-focusable). padding: none / sm / md (default) / lg. All variants share rounded-card and bg-surface-200 - a fix noted in the component's own source comment for a previous split between this component's radius and a legacy .app-card SCSS utility that disagreed with it.

Default

border + shadow-sm

Elevated

border + shadow-lg

Outlined

border-2, no shadow

Interactive

role="button", focusable, hover:shadow-md

Input

app-input - optional label rendered above via <label>, native <input> with type: text / email / password / number / url. No dedicated error input on the component itself - call sites express an error state by passing customClass (e.g. a border-danger override), shown below as the pattern used across the app (see profile.component.html, chat-room.component.html).

Textarea

app-textarea - same label/state pattern as app-input, plus rows (default 3). Identical padding/radius/focus classes, swapping horizontal padding for the taller pt-3 pb-3.

Default

Disabled

Select

app-select - a token-styled wrapper around the native <select>, chosen deliberately over a custom ARIA listbox rebuild (see the component's own doc comment): native <select> already has correct keyboard nav, screen-reader support, and platform-native mobile picker UI for free. Sits on bg-surface-300 rather than surface-200 like input/textarea. Options are projected via <ng-content> by each call site.

Default

Disabled
