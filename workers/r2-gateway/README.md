# Cloudflare-native R2 gateway

This Worker is the only application storage protocol boundary for Cloudflare R2.

The Angular applications and NestJS backend do not use an AWS SDK, an S3 client, access-key credentials or the R2 S3-compatible endpoint. Browser uploads use short-lived repository-signed Worker URLs. Backend reads and management operations use a separate Worker service token.

## Capabilities

```text
PUT    /v1/objects/:key
GET    /v1/objects/:key
HEAD   /v1/objects/:key
DELETE /v1/objects/:key

POST   /v1/multipart
PUT    /v1/multipart/:uploadId/parts/:partNumber
POST   /v1/multipart/:uploadId/complete
DELETE /v1/multipart/:uploadId
```

Browser `PUT` and multipart-part operations require a bounded HMAC signature generated by Nest. Management operations require:

```text
Authorization: Bearer <SERVICE_TOKEN>
```

## Required Cloudflare resources

- one production R2 bucket;
- one preview/non-production R2 bucket;
- one Worker deployment;
- an optional custom media domain;
- two independent random secrets:
  - `UPLOAD_SIGNING_SECRET`;
  - `SERVICE_TOKEN`.

Use at least 32 cryptographically random bytes for each secret. Do not reuse either secret for Cloudflare API access, Supabase, LiveKit or another application.

## Configuration

Edit `wrangler.jsonc` before production deployment:

```jsonc
{
  "name": "elgl-r2-gateway",
  "main": "src/gateway.js",
  "r2_buckets": [
    {
      "binding": "MEDIA_BUCKET",
      "bucket_name": "hellotalk-media",
      "preview_bucket_name": "hellotalk-media-preview"
    }
  ],
  "vars": {
    "PUBLIC_BASE_URL": "https://media.example.com",
    "ALLOWED_ORIGINS": "https://app.example.com,https://admin.example.com",
    "MAX_SINGLE_UPLOAD_BYTES": "26214400",
    "MAX_MULTIPART_PART_BYTES": "104857600",
    "MAX_SIGNED_URL_LIFETIME_SECONDS": "86400"
  }
}
```

`ALLOWED_ORIGINS` must contain only browser origins that may upload directly. It is not a wildcard by default.

The limits in the Worker are ceilings. Nest may sign a lower per-purpose limit.

## Local verification

```bash
cd workers/r2-gateway
npm test
npx wrangler dev
```

The unit suite uses an in-memory R2 binding contract and does not require a Cloudflare account.

For an end-to-end non-production test:

1. deploy to a preview Worker and preview bucket;
2. set preview secrets;
3. configure the backend with the preview Worker URL and matching secrets;
4. request an authenticated upload intent through Nest;
5. upload a small permitted fixture;
6. verify `HEAD`, authenticated `GET` and `DELETE` through the backend/gateway;
7. exercise multipart create, two part uploads, complete and abort;
8. verify an expired, tampered, over-size and wrong-origin upload is rejected.

Never use private user media as the deployment fixture.

## Secret installation

```bash
cd workers/r2-gateway
npx wrangler secret put UPLOAD_SIGNING_SECRET
npx wrangler secret put SERVICE_TOKEN
npx wrangler deploy
```

Configure matching backend values through the deployment secret store:

```text
CLOUDFLARE_R2_GATEWAY_URL
CLOUDFLARE_R2_SIGNING_SECRET
CLOUDFLARE_R2_SERVICE_TOKEN
CLOUDFLARE_R2_PUBLIC_URL
```

The names differ intentionally: Worker secrets are `UPLOAD_SIGNING_SECRET` and `SERVICE_TOKEN`; backend settings use the `CLOUDFLARE_R2_*` prefix.

## Signature contract

The signed payload is versioned and newline-delimited:

```text
cloudflare-r2-upload-v1
PUT
<object key>
<expiry epoch seconds>
<normalised content type>
<maximum bytes>
<upload ID or empty>
<part number or empty>
```

The Worker verifies:

- HMAC signature;
- expiry and maximum lifetime;
- HTTP method;
- exact key;
- exact content type;
- exact byte ceiling;
- multipart upload and part identity;
- allowed browser origin;
- streaming body size.

Changing this contract requires a versioned rollout that supports both deployed backend and Worker versions during the transition.

## Object-key policy

Object keys are server generated and validated.

Forbidden examples include:

- leading slash;
- `.` or `..` path segments;
- backslashes;
- control characters;
- excessive length;
- user-controlled bucket or arbitrary prefix selection.

Do not put email addresses, filenames containing personal data, message text, issue titles, tokens or credentials in keys.

## Public and private delivery

`PUBLIC_BASE_URL` is appropriate only for asset purposes explicitly approved as public.

Private media must resolve through an authenticated application/gateway path or another short-lived repository-signed delivery contract. A public URL must not be persisted as proof of authorization.

The current authenticated Worker `GET` response uses:

```text
Cache-Control: private, no-store
X-Content-Type-Options: nosniff
```

Asset-state and visibility work remains tracked by #7468.

## Rotation

Rotate one secret at a time:

1. deploy Worker support for the new and old key where an overlap is required;
2. update the backend signer or service token;
3. verify upload and management operations;
4. remove the old key after the maximum signed-URL lifetime;
5. review logs for old-key use without logging either secret.

For emergency service-token rotation, authenticated management operations may be briefly unavailable while browser upload signing remains independent.

## Failure and recovery

### Worker unavailable

- stop issuing new upload intents or surface an unavailable state;
- retain local user drafts through the offline platform;
- do not emit a media URL or sent message;
- restore the Worker or deploy the previous known-good Worker version;
- reconcile uploaded but unfinalised objects after recovery.

### R2 unavailable

- the Worker returns a bounded error;
- Nest and clients retain retryable state;
- no object is marked ready merely because transfer was attempted;
- review Cloudflare status and queue age;
- do not switch to an AWS service as an emergency fallback.

### Backend unavailable after upload

- retain the upload/asset operation ID;
- retry idempotent finalisation;
- do not upload duplicate objects blindly;
- reconcile abandoned intents through durable jobs.

### Suspected secret exposure

- rotate the affected secret immediately;
- invalidate or wait out signed URLs according to their maximum lifetime;
- review Worker request metadata without logging payloads or secrets;
- audit object creation/deletion and application finalisation records;
- follow the repository incident-response process.

## Observability

Use bounded metadata only:

- operation type;
- status and safe error code;
- purpose class where supplied by the application layer;
- byte-size bucket;
- duration;
- multipart part count;
- signature-expired/tampered/limit/origin rejection count.

Do not log:

- signatures or secrets;
- authorization headers;
- complete object keys when they can identify users;
- filenames, media content or request bodies;
- user IDs as metric labels.

## CI enforcement

Root verification runs:

```bash
npm run check:no-aws-sdk
npm run test:r2-gateway
```

The no-AWS check rejects direct AWS SDK packages, S3-specific adapters, AWS endpoints/credential variables and R2 access-key compatibility configuration in application source, manifests, lockfiles and environment examples.

## Rollback

Rollback uses the previous known-good Worker and backend release. It must preserve uploaded-but-unfinalised objects for reconciliation.

Rollback must not restore:

- an AWS SDK;
- an S3 client or egress adapter;
- R2 access-key credentials in application code;
- browser-visible bucket credentials;
- a fabricated media URL or successful upload state.
