# Unified Learner Knowledge Model Design

## Introduction
The Unified Learner Knowledge Model is designed to aggregate and synthesize data from various learning touchpoints within the application: vocabulary, flashcards, assessments, lessons, corrections, and conversation history. By centralizing this information, the system can build a comprehensive profile of what a user knows, what they are currently learning, concepts they struggle with, and content they have recently encountered. This profile serves as the foundation for deep personalization across all app features.

## Data Sources & Signals

The model ingests data from the following domains:

1. **Vocabulary & Hobby Tags**
   - **Data:** Target vocabulary sets associated with user interests (hobbies), base vocabulary, translated words, and cached user vocab.
   - **Signal:** Indicates topical areas of interest and words the user is likely exposed to or wants to learn.

2. **Flashcards (Spaced Repetition System - SRS)**
   - **Data:** `word_token`, `translation`, `srs_level`, `easiness_factor`, `repetitions`, `interval_days`, `next_review_at`.
   - **Signal:**
     - _Is Learning:_ Words currently in the review cycle.
     - _Repeatedly Gets Wrong:_ Low `easiness_factor` or words that frequently reset their `srs_level`.
     - _Knows:_ High `srs_level` and long `interval_days`.

3. **Assessments**
   - **Data:** Performance across specific `AssessmentSkill` (speaking, listening, reading, writing, grammar, vocabulary) and `AssessmentCategory` (self_assessment, comprehension, production, interaction) at varying difficulty levels.
   - **Signal:** Establishes baseline proficiency and highlights structural strengths and weaknesses.

4. **Lessons**
   - **Data:** Completed lessons, module progress, and scores.
   - **Signal:** Defines the formal curriculum boundaries of what the user has recently encountered and officially "covered."

5. **Corrections (Moments & NLP)**
   - **Data:** Social corrections on "Moments" from the community, and automated `wordCorrections` generated by the NLP service.
   - **Signal:** Identifies organic, real-world mistakes. Recurring corrections on the same grammar structures or vocabulary pinpoint persistent learning gaps (what the user repeatedly gets wrong).

6. **Conversation History (AI & Human)**
   - **Data:** Chat logs, utilized vocabulary during AI roleplay scenarios, and conversation context.
   - **Signal:** Reveals active vocabulary (what the user can produce vs. just recognize) and recently encountered contexts.

## The Unified Model Structure

The core of the system is the `LearnerKnowledgeProfile`, updated asynchronously as the user interacts with the app.

```typescript
interface LearnerKnowledgeProfile {
  userId: string;
  language: string;
  overallProficiency: CEFRLevel;

  // Granular skill tracking (0.0 to 1.0)
  skills: {
    speaking: number;
    listening: number;
    reading: number;
    writing: number;
    grammar: number;
    vocabulary: number;
  };

  // The state of specific vocabulary words or grammar rules
  knowledgeItems: Map<string, KnowledgeItem>;

  // Recent activity context
  recentEncounters: RecentEncounter[];
}

interface KnowledgeItem {
  id: string; // e.g., "vocab:gato" or "grammar:subjunctive"
  type: 'vocabulary' | 'grammar' | 'phrase';

  // Knowledge State
  status: 'new' | 'learning' | 'known' | 'struggling';

  // Metrics
  confidenceScore: number; // Based on SRS easiness, assessment results, and correct usage in chat
  errorFrequency: number; // How often this item is corrected in Moments/Chat

  // Link to raw data
  sourceIds: {
    flashcardId?: string;
    lessonIds?: string[];
    assessmentIds?: string[];
  };

  lastEncounteredAt: Date;
}

interface RecentEncounter {
  topic: string; // e.g., "ordering-coffee"
  source: 'ai_conversation' | 'lesson' | 'moment';
  timestamp: Date;
}
```

## Personalization Strategies

By querying the `LearnerKnowledgeProfile`, different modules can adapt dynamically:

1. **AI Conversation Prompts:**
   - Inject words from `knowledgeItems` with status `learning` into the AI's system prompt (already partially implemented via `FlashcardsService`).
   - Instruct the AI to explicitly test grammar rules where the user has a high `errorFrequency`.
   - Set the conversation scenario based on `recentEncounters` or user hobbies.

2. **Content Recommendation:**
   - Suggest lessons that target the lowest scores in the `skills` breakdown.
   - Generate custom reading exercises that embed `struggling` vocabulary items within contexts related to the user's hobbies.

3. **Spaced Repetition & Flashcard Generation:**
   - Automatically generate new flashcards when the NLP service detects a user making the same vocabulary mistake multiple times in AI Conversations or Moments.
   - Prioritize flashcards in the review queue if the user recently encountered the word in a lesson but hasn't successfully used it in a conversation.

4. **Assessment Calibration:**
   - Dynamically adjust the difficulty of assessment questions. If the user's `confidenceScore` for a specific grammar rule is high, the assessment engine can serve advanced edge-case questions to validate true mastery.

## Implementation Roadmap

1. **Schema Design:** Create the Supabase tables/views to persist the `LearnerKnowledgeProfile` and `KnowledgeItem` entities.
2. **Event Aggregator:** Implement an event bus or background worker that listens for app events (flashcard review, lesson complete, NLP correction generated) and updates the knowledge profile.
3. **API Layer:** Expose read-only endpoints and internal services for feature modules (AI Conversation, Lessons, Recommendations) to fetch the user's profile.
4. **Integration:** Update the `AiConversationService` and `RecommendationsService` to consume the unified profile instead of querying individual services directly.
