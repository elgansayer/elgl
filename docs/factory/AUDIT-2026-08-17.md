# Factory deep audit: 2026-08-17

## Verdict

The Factory is not working flawlessly yet. Its provider-neutral source, protected merge policy, single-owner
deployment, durable reconciliation, and real provider fallback are now operating in a production canary. It has
not yet completed the required implementation, independent review, CI, merge, and issue-closure cycle, and the
health recovery timer remains inactive during the canary.

At 09:14 UTC on 17 August 2026, the canonical daemon was failed, a retired competing service was restart-looping,
the installed unit was stale, provider readiness was unknown, and GitHub did not require Factory statuses. Those
initial findings explain the previous absence of Factory output, but they are superseded by the chronological
repairs and current readiness matrix below. No responsible engineering audit should describe the current partial
canary as 100 per cent autonomous until the whole protected cycle completes.

This audit is the current readiness verdict. The larger implementation history and control-by-control review are
retained in [AUDIT-2026-08-16.md](AUDIT-2026-08-16.md).

## Post-audit crash investigation: 17:27 UTC

The operator started the deployed service, but it entered a restart loop. `providers check` passed and
OpenHands was the only usable configured provider. The daemon then failed its fail-closed
`agent-process-isolation` and `verification-isolation` checks and exited with status 1.

The cause was reproduced with the installed systemd restrictions: `ProtectKernelLogs=true` caused both
the provider and verification `unshare --mount-proc` sandboxes to fail with `Operation not permitted`.
The main daemon unit now omits that one incompatible directive while retaining the remaining process,
home, filesystem, cgroup, and network boundaries. The root watchdog retains its kernel-log protection.
At that point the unit change was not live. The later activation installed it and produced a fresh heartbeat.

The same live diagnostics also showed that Claude, Codex, and OpenCode are not installed on the service
user's PATH, and the OpenAI credential is expired. Those are provider readiness warnings, not the cause
of this crash because OpenHands remains configured as an emergency provider.

## Post-audit provider execution incident: 20:24 UTC

After the dedicated service account was authenticated and the daemon was started, durable provider history
showed that discovery and fallback were running but no agent could complete an execution. The primary software
defect was a Codex option incompatibility: the adapter passed both `--approve-for-me` and an explicit
`--sandbox workspace-write`, which the installed Codex CLI rejects before starting a model session.

The remaining providers exposed independent capacity conditions. Claude was authenticated through a Pro
subscription but had reached its monthly spend limit. Google was authenticated but its individual quota was
temporarily exhausted. OpenCode was authenticated but reported insufficient balance. The OpenHands emergency
credential had expired. Google, OpenCode, and Claude quota messages were incorrectly classified as generic
transport failures, causing an unnecessary same-provider retry and a short generic circuit cooldown.

This revision removes the conflicting Codex sandbox option, recognises the observed quota responses, and parses
Google reset durations such as `2h12m46s` into bounded retry times. Regression tests cover the command contract
and each observed failure message. A bounded, non-mutating Codex canary run as `hellotalk-factory` with the
corrected adapter arguments completed successfully and left the repository unchanged.

The daemon was deliberately stopped while this correction and the complete repository verification ran. This
historical deployment requirement was later satisfied by the live fallback and durable advancement described
below.

The same activation exposed a watchdog startup race. Provider preflight plus the first large GitHub refresh took
about 85 seconds, while the watchdog retried a missing heartbeat every 20 seconds. It therefore terminated each
healthy daemon before the first scheduling cycle could publish liveness. The daemon now writes an owned initial
heartbeat before provider probing and GitHub refresh. The existing freshness limit still recovers a process that
later stops updating, and a regression test fixes the startup ordering contract. The watchdog now also gives a
restarted unit 30 seconds, configurable through `FACTORY_WATCHDOG_RESTART_GRACE_SECONDS`, before judging the new
heartbeat. This removes the remaining boundary race observed near the old 20-second retry point.

The recovered daemon discovered PR #7348 but selected three priority-0 issue repairs instead. External PRs use
priority 5, so a sustained guardian backlog could starve every independent review and leave all otherwise-green
PRs permanently blocked. Parallel scheduling now reserves at most one slot for the oldest runnable PR when no
review is active. Critical issue work retains every other slot.

The first production run then exposed two related classification and ordering defects. A responsive Codex run
that made no repository change was labelled `invalid_agent_output`, retried, and opened the provider circuit.
No-change implementation and repair outcomes are task failures, not evidence that Codex is unavailable, so they
now stop provider rotation and leave the provider circuit healthy. External pull requests also used fixed
priority 5 even when a trusted urgency label was present. PR discovery now honours `guardian-alert`,
`priority:critical`, and `priority:high` within the bounded review lane while preserving priority 5 as the normal
default.

The queue audit also found 94 open high-priority workflow incidents left by the retired producer behaviour: 88
were duplicate pull-request failures already owned by the PR repair state, and six were old `main` failures with
newer successful CI runs. Their source evidence was verified against current GitHub issue, PR, branch, and run
state before they were closed without per-issue comments. Closing them is reversible. The current
`on-failure.yml` already excludes pull-request failures, so this was a bounded legacy cleanup rather than a new
recurring mutation path.

OpenHands SDK child processes were also writing raw third-party output directly to the systemd journal. One
failed attempt emitted a large repository transcript and provider error page. SDK children now redirect stdout
and stderr to the null device while returning their bounded typed error through the existing pipe. CLI provider
output remains bounded and redacted by `AgentProcessRunner`, and OpenHands retains its own dedicated conversation
diagnostics where the SDK creates them.

The production cleanup canary exposed a final scale boundary in the durable reconciliation path. Retiring many
closed jobs rewrote the complete 11 MB job snapshot once per job, and the synchronous refresh prevented the main
loop from publishing a fresh heartbeat while Git removed old worktrees. Reconciliation now merges every retired
job in one generation-checked write. The blocking control-plane pass runs on its own single-worker executor while
the owner loop publishes liveness every ten seconds. Live worker identifiers remain excluded, sibling worker
transitions are merged from current durable state, and the watchdog can distinguish slow cleanup from a dead
daemon.

That canary also reached the real isolated repository gate and found that `uv` was omitted from its effective
path. The verifier derived the environment from the fully resolved Python executable, which followed the virtual
environment symlink back to the system interpreter. It now derives the path from `sys.prefix`, preserving
`/opt/hellotalk-factory/venv/bin` inside the credential-free, network-isolated namespace. A regression test uses
a deliberately separate virtual-environment prefix so a future symlink regression cannot pass unnoticed.

A later deployment exposed a second, distinct `uv` lifecycle failure. The bootstrap installed `uv` into the
same environment that `uv sync` then reconciled exactly against the Factory lock, so the sync could remove its
own executable as an extraneous package. Doctor then failed, deployment rolled back, and repository verification
could not enter review. Bootstrap and deployment now use `--inexact` to preserve the pinned tool. Deployment also
restores `uv==0.12.5` through the existing virtual-environment Python when repairing a host affected by the old
behaviour, then verifies that the executable survived the refresh.

## Post-audit restart incident: 00:00 UTC on 18 August 2026

A trusted control-panel restart exposed another availability boundary. The old installed preflight rejected a
developer-owned Claude process solely because its command contained `--dangerously-skip-permissions`, even though
the process was attached to an operator TTY rather than running as a detached autonomous executor. The detector
now reads process TTY state. Detached unrestricted providers remain fail-closed, while terminal-attached operator
sessions can coexist with the Factory's isolated service-user worktrees.

The complete Factory suite then reproduced a separate durable lease race. Worker threads captured their wall
clock before waiting for the lease lock. A thread with a slightly earlier timestamp could reject a sibling lease
whose valid expiry was only milliseconds later, then overwrite that lease. Implicit timestamps are now captured
inside the mutation lock, and the existing one-minute acquisition clock-skew allowance is applied consistently
to expiry validation. The focused module and 100 consecutive parallel acquisition stress runs pass.

These source repairs do not prove live recovery. The installed daemon still predates the corrected Codex command,
owner-only CI bypass validation, interactive-process classification, and deployment failure trap. A privileged
deployment of current `origin/main`, followed by a complete issue-to-merge canary, remains mandatory.

The source review started from `main` at `8abd960edfdee89a5a43832fa649ed13ff1afb7b` and covered:

- issue and pull-request discovery, queue selection, durable jobs, retries, quarantine, and restart recovery;
- worktree, branch, commit, push, verification, review, status, CI repair, and merge ownership;
- every AI-backed phase and every provider adapter;
- provider process isolation, environment filtering, timeout, cancellation, and shutdown;
- health, circuit, cooldown, capacity, fallback, diversity, provenance, and metrics;
- production configuration, systemd, deployment, doctor, workflows, and active documentation;
- current vendor model guidance and the account-visible developer-user CLI catalogues;
- the live host and GitHub control plane using read-only commands.

Local developer authentication proves only that the installed CLIs can see the configured model names for that
developer account. It does not prove that `hellotalk-factory`, whose home is
`/var/lib/hellotalk-factory/home`, is authenticated or has the same entitlements. A later service-user activation
canary supplied the missing evidence and produced the follow-up results below.

The exact Factory package at `1d6720b40` was installed into the production virtual environment. The service has
remained active since 21:54:54 UTC with zero systemd restarts, the retired meta-agent unit is absent, and the
daemon completed its large reconciliation while continuing to publish heartbeat updates. The recovery timer is
still deliberately inactive during the canary and must be re-enabled before declaring production activation
complete.

The live router selected Claude first, classified its subscription limit as provider quota, and fell back to
Codex. Codex accepted real issue jobs. Another review attempt skipped a busy Claude slot, tried OpenCode, then
the OpenHands emergency adapter, and durably deferred when neither had capacity. OpenCode's service-user
credential and model catalogue are valid, but a tiny repository-free generation returned `insufficient balance`.
OpenHands has no independent usable credential and should be disabled in the operator policy until that changes.
These are capacity results, not evidence that repeated login or key replacement is required.

The canary also found one reviewed-SHA recovery defect. PR #7348 advanced remotely while its durable job still
held quality findings from the previous head. `QUALITY_REPAIRING` would therefore act on stale evidence before
the existing CI-state SHA guard ran. The pipeline now checks the current PR head before code review, quality
repair, and PR-backed verification, clears stale findings, rebuilds the worktree, republishes pending review
status, verifies the new head, and only then resumes review. Regression coverage exercises every guarded
verification, review, repair, CI, and merge state.

The required status remained absent on every sampled open PR head after that run. The earlier bounded review lane
reserved a worker but submitted it after issue workers. With Codex as the only provider able to execute, those
workers acquired both Codex leases before the PR reached routing. The PR then encountered quota or authentication
failures on the remaining providers and backed off without publishing a successful review. Queue selection now
submits one runnable PR first, blocks a second simultaneous PR lane, and reserves one provider slot from new issue
jobs while the selected PR worker is active. This preserves issue throughput on the remaining slots without
weakening or fabricating `factory/independent-review`.

## Critical findings

### P0 resolved: the production daemon is running

The corrected package and unit are active and durable work has advanced without restart churn. Final activation
still requires this revision to merge through protected `main`, deployment from `main`, and health-timer startup.

### P0 resolved: GitHub enforces Factory review

The baseline ruleset requires a pull request plus strict `CI / required` on an up-to-date branch. A separate
review-only ruleset requires `factory/independent-review`. The sole bypass actor on both is the exact
repository-owner user in pull-request mode, allowing deliberate manual waiver of CI, review, or both without
permitting direct pushes. Factory automation still requires both statuses and never invokes the owner bypass.
`CI / required` is pinned to GitHub Actions. The Factory status still needs a dedicated GitHub App so the review
ruleset can pin its expected publisher rather than trusting only the context name.

### P0 resolved: one autonomous execution owner

The retired `hellotalk-meta-agent.service` is absent. Interactive developer sessions remain outside Factory
evidence and must never be counted as autonomous production work, but they no longer constitute a second daemon.

### P1: production routing had regressed to OpenHands-only

The provider-neutral implementation entered history in `36448822f`, but later commits beginning with
`21ae8717b` disabled every direct provider and reduced every production route to `openhands`. Follow-up tests and
documents then encoded the regression as intended behaviour. That configuration could never satisfy the requested
Claude, Codex, Google, OpenCode, then OpenHands fallback policy.

This revision restores direct Claude, Codex, and OpenCode subscription adapters, keeps Google present but disabled
until its service-user canary, places OpenHands last and emergency-only, and adds regression assertions for the
exact phase routes. OpenHands remains one provider beneath the Factory rather than a competing control plane.

### P1: deployment deliberately preserves operator routing

`scripts/deploy-and-start-factory.sh` refreshes `agents.example.json` but preserves an existing
`/etc/hellotalk-factory/agents.json`. That is the correct safe default, but it means deploying this source does not
automatically correct an older OpenHands-only operator file. The operator must compare and deliberately reconcile
the two files before starting the canary.

### P1: service-account provider capacity is constrained

Service-user probes and real attempts now show:

- Claude Code is authenticated through `claude.ai`, but the account has reached its current monthly spend limit;
- Codex CLI is authenticated through ChatGPT and is accepting real Factory jobs;
- Antigravity is authenticated but currently reports subscription quota exhaustion;
- OpenCode 1.18.15 has an OpenCode Go credential and every configured model slug, but generation reports
  `insufficient balance` for that workspace;
- OpenHands has no independent usable SDK credential, and its stale OpenAI OAuth path fails authentication.

Do not place OpenCode credentials in the repository `.env`, and do not repeat login for a capacity response. Use
the CLI-owned service-user auth store, wait for or add capacity, disable OpenHands until separately authenticated,
and let the router continue with Codex while the other circuits cool down.

## Source architecture review

The current source preserves the important Factory guarantees:

- `FactoryPipeline` owns the lifecycle and maps all AI-backed phases to typed `AgentPhase` values;
- provider implementation details remain in independent adapters rather than phase branches;
- candidate order comes from validated configuration and emergency providers are demoted;
- disabled, unhealthy, cooling-down, unsupported, excluded, and optionally busy providers are skipped;
- provider retries and the candidate set are finite;
- provider-side failures update durable health and can fall through to another provider;
- repository, test, task, policy, and internal failures return to Factory repair or failure handling;
- capacity leases are generation-aware and released in `finally` paths;
- no-provider capacity defers a job without consuming a task attempt;
- health, cooldowns, history, task state, and reviewed SHA survive daemon restart;
- direct CLIs use argument vectors, stdin, bounded output, process groups, TERM then KILL, and no shell command
  constructed from issue text;
- API keys, GitHub tokens, alerting secrets, proxy variables, other provider sessions, and unrelated host paths are
  excluded from direct subscription-provider environments;
- verification runs separately without provider credentials or network access;
- stale review artefacts are deleted before every attempt and valid file output remains authoritative;
- every repair returns to local verification and independent review;
- merge eligibility requires literal success for both canonical statuses and an unchanged head SHA;
- the autonomous merge call uses `--match-head-commit` and never uses administrator bypass;
- the exact repository owner can manually waive either required PR status in audited pull-request mode, while the
  Factory service identity has no bypass authority and still requires literal success from both statuses.

This is a strong resilient design. The failures found in this audit do not justify replacing the Factory with a
single CLI. They justify deploying and enforcing the Factory that already exists.

   queue selection can starve newer same-priority work behind a very large old backlog.
2. [Issue 6938](https://github.com/elgansayer/elgl/issues/6938): timestamps and state alone do not provide a rich
   progress signal or proactive stagnation recovery.

   last-known-good self-update and rollback remain unfinished.
4. [Issue 6946](https://github.com/elgansayer/elgl/issues/6946): the health timer is host-local; an independent
   external dead-man controller remains unfinished.
5. [Issue 6945](https://github.com/elgansayer/elgl/issues/6945): ambiguous or partially recovered work needs a
   stronger never-discard evidence path.
6. [Issue 6936](https://github.com/elgansayer/elgl/issues/6936): pull-request churn and current-main replay loops
   need stronger bounds.
7. Security review does not yet require an authoritative structured report. A successful provider no-op or
   refusal can be accepted as no findings before deterministic verification runs.
8. CI repair receives failed check names and mergeability, not a bounded redacted log excerpt or base-branch
   attribution.
9. Google and OpenCode lack the equally strong provider-native system-instruction channels used by Claude,
   Codex, and OpenHands in the verified non-interactive contracts.
10. Required status names are checked, but publisher identity is not attested without a dedicated GitHub App and
    ruleset integration pinning.
11. PAYG budget fields are hooks and observability, not exact enforceable cross-vendor billing caps.

    a fork branch.
13. OpenHands records outer `openhands-sdk` provenance while its inner model attribution remains in a separate

    empirical promotion.

## 2026-08-18 ownership-label drift repair

The live GitHub audit found 1,210 open issues carrying `factory-active`, 929 carrying retired `swarm-active`, and
46 carrying only the retired marker. These labels had accumulated across older executors and interrupted jobs.
They could incorrectly claim ownership, admit otherwise untrusted work, or keep eligible issues outside discovery.

The Factory now treats durable non-terminal jobs plus currently protected workers as authoritative ownership. It
clears stale current and retired markers in a configurable batch of 25 per scheduler refresh, restores
`factory-ready` to preserve trusted intake, and posts no comments. The batch is constrained to 1 through 100, so
historical cleanup converges without a startup storm or unbounded GitHub API use. Normal successful completion
also removes ownership before closing the source issue, preventing new drift after merge.

## Definition of safe autonomy

Autonomy means the Factory can discover eligible work, recover durable state, route around provider-side
failures, wait through provider exhaustion, verify changes, obtain independent review, repair attributable
failures, and merge only the reviewed head without routine operator intervention.

It does not mean bypassing authentication renewal, ambiguous product decisions, repository policy failures,
unavailable GitHub infrastructure, security findings, or every-provider exhaustion. In those cases, safe autonomy
keeps the daemon and durable queue recoverable while stopping unsafe task or merge progress. Claiming 100 per cent
operation requires measured production evidence, not only source code and mocked tests.
