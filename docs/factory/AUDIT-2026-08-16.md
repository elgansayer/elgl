# Factory engineering audit: 2026-08-16, updated 2026-08-17

> Historical audit. The current production-readiness verdict and delta review are in
> [AUDIT-2026-08-17.md](AUDIT-2026-08-17.md).

## Executive result

The inspected host is not autonomously processing work. At the initial inspection,
`hellotalk-factory.service` had reached systemd start-limit failure, the health timer was inactive, and the
canonical `/etc`, `/var/lib`, and `/opt` Factory installation paths were absent. A partial host repair later
created those paths, but the 2026-08-17 03:49 UTC recheck still found the Factory service failed, the health timer
inactive, the retired meta-agent enabled and restart-looping, and a separate unrestricted Claude process working
from the development checkout.

The GitHub side was also not fail-closed. PR #7263 was created while the Factory daemon was down and GitHub
attributes its 2026-08-17 03:45 UTC merge to the repository owner account. It had no Factory labels, no reviews,
and no `factory/independent-review` status. The active `main` ruleset required a pull request but did not require
`CI / required` or `factory/independent-review`, and it contained broad always-bypass actors. That activity cannot
be credited to the Factory and demonstrates that a second execution owner could create, repair, and merge work
around its durable state and review gate.

The repository implementation now has one control plane, provider-neutral routing, direct subscription adapters,
typed fallback, durable health and capacity, cross-provider review, structured-output fallback, stale-head
recovery, graceful shutdown, service-user diagnostics, production routing configuration, and main-only Factory
deployment.

This is source-level, local CLI-contract, and mocked-runtime proof. It is not proof that the production host is
healthy. Before unattended operation can be declared, the operator must remove competing executors, enforce the
two Factory status checks in GitHub rules, deploy the new `main`, authenticate enabled CLIs in the service account
home, pass online doctor, and complete a small end-to-end canary.

## Scope reviewed

The audit traced:

- issue and external PR discovery;
- durable reconciliation and daemon generation ownership;
- worktree creation, retirement, recovery archives, branches, commits, pushes, and merge controls;
- every AI-backed pipeline phase;
- provider process invocation, stdin, environment, exit status, timeout, cancellation, and output bounds;
- provider health, circuits, cooldowns, leases, fallback, rotation, history, and metrics;
- `.factory-review.json` and `.factory-architect.json` lifecycle;
- daemon restart and shutdown;
- doctor, systemd, deployment, and watchdog behaviour;
- GitHub CI and scheduled merge workflow;
- current provider CLI and model guidance from primary vendor documentation;
- tests, lint, typing, shell scripts, and documentation consistency.

## Root causes and blocking defects

1. `hellotalk-factory.service` was failed and start-limit-hit, so no scheduler was discovering or advancing jobs.
2. `hellotalk-factory-health.timer` was not sustaining the intended recovery loop.
3. `hellotalk-meta-agent.service` referenced a wrong path and repeatedly restarted.
4. The meta-agent was architecturally unsafe because it invoked Claude directly in the base checkout instead of
   repairing through durable Factory state and isolated worktrees.
5. Earlier CLI wrappers located host executables, then attempted to invoke them in a networkless worker image
   without those binaries or subscription credentials.
6. The PTY wrapper inferred success from output text and did not provide reliable exit status, timeout, or process
   cleanup.
7. Provider selection lacked durable concurrency, typed structured-output failure, complete provenance, and a
   no-provider deferral path.
8. Review and architect artefacts could appear as task changes and drive false repair loops.
9. Reviewed external PRs were excluded from discovery, so a later head update could leave stale durable review
   state indefinitely.
10. CI repair prompts did not include the failed check identities returned by GitHub.
11. Local verification failures remained in `VERIFYING`, so the same failed commands repeated without invoking a
    repair provider.
12. A startup probe with zero usable providers exited the daemon. systemd could then hit its start limit before a
    provider recovered.
13. Persisted half-open circuit state had no lease expiry, so a crash during the probe could exclude that provider
    forever.
14. Repeated empty implementation diffs could close an issue as already satisfied without acceptance evidence.
15. Queue priority ignored `priority:*` labels, allowing old ordinary backlog to delay urgent workflow failures.
16. Deployment refreshed daemon source but could leave Python dependencies, shared Node modules, Cypress, and the
    worker image on an older revision.
17. OpenHands inner SDK failures lost their typed classification at the outer adapter and could suppress valid
    provider fallback.
18. Independent review excluded only successful mutating attempts even though failed or timed-out agents may
    already have changed the worktree.
19. Secret scrubbing removed the daemon's GitHub token from the ambient process environment before Git pushes.
    On a clean service account, the host credential helper therefore had no authenticated credential and task
    branches could never reach GitHub even after implementation succeeded.
20. The pipeline armed GitHub native auto-merge before the final scheduled gate. A later human requested-changes
    review could race that native queue when repository branch rules did not independently enforce reviews.
21. GitHub rules required a pull request but did not require either Factory status context and allowed broad
    always-bypass actors, so another authenticated actor could merge around the independent-review workflow.
22. Repository-local Factory verification ran `pytest` but omitted Ruff and mypy. CI caught those failures only
    after a branch push, creating avoidable repair cycles.
23. A separate unrestricted Claude process and the retired meta-agent could operate outside Factory leases,
    worktrees, provider history, verification, and merge ownership.
24. Durable job read-modify-write operations were protected only inside one Python process. Concurrent doctor,
    backlog, watchdog, or daemon processes could overwrite sibling job transitions.
25. Provider health commands ran with the canonical repository as their working directory, unnecessarily exposing
    a writable base checkout to nominally read-only probes.
26. Per-job provider history had no size bound, allowing `jobs.json` to grow indefinitely on a long-lived task.
27. Shutdown tracked direct provider and OpenHands children but not trusted Git, verification, or repository
    subprocess groups.
28. The OpenHands compatibility runner received the full typed Factory configuration, including unrelated GitHub
    and alerting credentials, through multiprocessing serialisation.
29. Review labels were invalidated at head-change and repair transitions, but an interrupted AI phase could begin
    while old merge-eligibility labels and a successful SHA status remained reusable.
30. Durable jobs were stamped with a daemon generation, but `JobStore` did not reject writes from a stale
    generation after runtime takeover.
31. Direct-provider mount isolation hid the service home, Factory state, logs, and `/tmp`, but left the
    service-owned deployment build context writable and left `/var/tmp` and shared memory visible across attempts.
32. An unused legacy `SandboxRunner` remained available with an unbounded, untracked subprocess path outside the
    hardened provider and shutdown lifecycle.
33. Weekly architecture runs used a transient job, so provider provenance disappeared after the cycle and an
    architecture provider that changed documentation could review its own pull request.
34. The operator CLI made itself non-dumpable only after parsing the root-managed environment, leaving a short
    same-user procfs credential-read window during startup.
35. This public repository admitted every open issue and same-repository pull request by default. Untrusted text
    could therefore reach a networked provider that necessarily reads its own subscription session.
36. GitHub rules checked required context names but did not pin those contexts to expected GitHub App sources, so
    a repository write actor could publish a legacy status with the same name.
37. Direct provider namespaces hide control-plane and sibling-provider secrets, but each provider necessarily
    retains its own writable subscription session and vendor network access.
38. The final systemd unit diagnostic was the remaining direct subprocess without an execution timeout or an
    explicit minimal environment.
39. Malformed Claude authentication output and an empty Antigravity model catalogue were marked degraded even
    though degraded providers are eligible for task routing.
40. Networkless repository verification hid Factory state, logs, home, and `/tmp`, but still shared `/var/tmp`
    and shared memory and did not independently remount the deployed Factory tree read-only.
41. Architect duplicate-title detection still included public issues which had not passed trusted intake, allowing
    an untrusted lower-numbered title to suppress a trusted proposal without ever becoming executable work.

## Corrections made

### Orchestration

- Added typed `AgentPhase`, `AgentRequest`, `AgentResult`, `AgentFailure`, `ProviderHealth`, and provider protocol.
- Wrapped Claude Code, Codex CLI, configurable Google CLI, OpenCode, and existing OpenHands execution as adapters.
- Kept the Factory state machine and all Git/GitHub authority outside providers.
- Routed implementation, security, quality repair, review, CI repair, architecture, and general action uniformly.
- Replaced LLM triage with deterministic triage so intake cannot fail because an agent is unavailable.

### Reliability

- Added bounded same-provider retry and finite typed fallback.
- Made task, test, repository, and policy failures prove provider responsiveness and reset older transient circuit
  strikes without making those task-side failures eligible for provider rotation.
- Normalised provider contract violations that return an unclassified failure into typed invalid output before
  provenance, circuit, retry, and fallback handling.
- Added durable per-failure circuits, cooldowns, atomic half-open probes, and health refresh.
- Made Google and OpenCode health fail before scheduling when configured phase models are absent from their
  authenticated account catalogues.
- Added expiring half-open probe leases and cache invalidation before recovery probes.
- Added generation-aware provider capacity leases and busy-provider bypass.
- Sized each capacity lease for the complete bounded same-provider retry window so a second attempt cannot
  outlive its concurrency reservation.
- Rejected every durable job mutation from a stale daemon generation, matching the task-lease ownership guard and
  preventing an old worker from overwriting post-restart state.
- Remounted `/opt/hellotalk-factory` read-only and replaced `/var/tmp` and `/dev/shm` with private temporary
  filesystems inside every direct-provider namespace.
- Removed the unused legacy sandbox module so every provider execution now goes through the single bounded,
  tracked process boundary or the OpenHands SDK adapter.
- Persisted architecture provider history in the durable cycle state and copied it into generated pull-request
  jobs, where mutating architecture providers are excluded from independent review when alternatives exist.
- Enabled process credential protection before loading or parsing Factory configuration and secrets.
- Added backwards-compatible trusted-intake policy. The production environment automatically accepts configured
  repository actors and Factory architecture work, while other public authors require a maintainer-controlled
  admission label. Untrusted lower-numbered issues cannot suppress trusted work by pre-empting its title.
- Rejected malformed, timezone-naive, future-acquired, and overlong provider and task leases, and added a
  cross-process task-lease lock so operator reconciliation cannot race the daemon.
- Added `NO_PROVIDER_AVAILABLE` deferral semantics without burning task attempts.
- Persisted a bounded no-provider reason even when no provider process started.
- Corrected the durable retry bridge to consume the router's `failure_classification` field while retaining the
  legacy `kind` key, so typed provider evidence survives restart and controls the right backoff class.
- Kept the daemon online when all providers are temporarily unavailable so durable work can recover.
- Added registered process groups, real exit status, output limits, timeout, SIGTERM, and forced kill fallback.
- Added daemon shutdown integration for direct CLI, OpenHands, Git, verification, and repository children.
- Bounded the final systemd unit diagnostic and removed unrelated inherited environment from that child.
- Made authentication and model-catalogue probes fail closed when they cannot prove a usable session.
- Gave repository verification private `/var/tmp` and shared-memory filesystems and a read-only deployed Factory
  tree, matching the direct-provider host-integrity boundary.
- Applied trusted intake to architect duplicate-title evidence while retaining admitted blocked and quarantined
  work in deduplication.
- Added TERM-to-KILL escalation for OpenHands process groups whose graceful SDK pause handler stalls, and made
  shutdown cancellation defer the durable job without consuming an attempt.
- Added atomic state recovery using last-known-good backups.
- Added schema validation, a cross-process job-state read-modify-write lock, and architect retry/recovery state.
- Bounded each job's provider history to the latest 500 attempts, including backwards-compatible deserialisation.
- Added worker-age watchdog recovery in addition to the daemon heartbeat check.

### Quality and merge safety

- Preserved repository-native verification before push and after every repair.
- Made Factory-local verification run Ruff formatting, Ruff lint, mypy, and pytest before a branch push.
- Routed deterministic local verification failures into bounded quality repair for issue and external PR work.
- Moved structured report validation inside provider attempts so malformed output can retry and fall through.
- Cleared stale reports before each attempt and deleted valid reports before diff detection.
- Recognised acceptance criteria beneath any standard Markdown heading level, preventing a `# Acceptance
criteria` issue from bypassing criterion-by-criterion review.
- Excluded every attempted code-mutating provider from independent review when alternatives exist.
- Rotated quality and CI repair providers based on history.
- Added failed check names and mergeability to CI repair context.
- Rediscovered labelled external PRs and invalidated review labels whenever GitHub reports a new head.
- Excluded cross-repository PRs from the mutating queue because the repository token cannot safely push their
  fork branches; a future read-only review path can handle them explicitly.
- Rebuilt changed PRs from the remote branch and re-reviewed the actual checked-out SHA.
- Made a `BEHIND` pull request request a GitHub base update bound to the inspected SHA, clear review eligibility,
  and re-enter local verification and independent review at the resulting head instead of stalling in the merge
  queue.
- Preserved the final GitHub merge workflow and banned administrator merge bypass.
- Required literal `SUCCESS` for both repository-required status contexts; `SKIPPED` and `NEUTRAL` fail closed.
- Allowed safe duplicate required-context rollup entries after reruns only when every duplicate reports literal
  `SUCCESS`, avoiding an exactly-one-entry merge stall without weakening the gate.
- Made the independent merge workflow reject human `CHANGES_REQUESTED` reviews even when branch rules do not
  enforce that review decision themselves.
- Removed native auto-merge activation. The scheduled workflow is now the only merge authority, re-reads the
  current checks, mergeability, and human review decision, then binds squash merge atomically to the inspected
  head with `--match-head-commit`.
- Removed empty-diff issue closure because an agent no-op is not evidence that acceptance criteria are met.
- Removed `factory-reviewed` and `factory-review`, then reset `factory/independent-review` to `PENDING`, before
  every PR-backed AI phase. Refresh and base-update paths also invalidate the current or new SHA before
  verification, so an interruption cannot leave stale merge eligibility reusable while code or review state may
  be changing.
- Added an online doctor check that fails production readiness unless one active, no-bypass GitHub ruleset requires
  a pull request, `CI / required`, and `factory/independent-review` on the configured base branch.

### Security

- Built provider commands as argument vectors without `shell=True`.
- Validated persisted external pull-request branch names before fetch or push, including rejection of option-like
  refs and Git-prohibited path components.
- Passed prompts through stdin or a mode `0600` temporary file.
- Loaded control prompts from the dedicated Factory checkout, never an agent-modifiable task worktree.
- Separated trusted policy from untrusted task data through Claude's system-prompt and Codex's developer-prompt
  channels.
- Disabled Claude customisation with safe mode and made Codex ignore personal configuration and repository rule
  files so service-user preferences cannot silently alter Factory policy.
- Removed the obsolete Claude `--max-turns` invocation after checking the installed 2.1.233 CLI contract. Phase
  process timeouts remain the authoritative execution bound.
- Removed API keys and daemon tokens from direct subscription process environments.
- Stopped the environment installer from copying arbitrary `GEMINI_*` variables into the daemon configuration
  and forced the retired `GEMINI_ENABLED` flag to false during migration. This prevents a legacy repository
  `.env` from making the new subscription router fail before startup.
- Made `factory.env` root-only and scrubbed parsed secret variables before child execution.
- Bounded and redacted stored diagnostics and omitted raw transcripts from normal logs.
- Retained networkless rootless Podman and worktree-only file editing for the OpenHands transport.
- Removed host PID namespace access from the rootless Podman fallback so an agent cannot inspect concurrent
  service processes through `/proc`.
- Scoped the GitHub token to short-lived Factory-owned Git subprocess environments only. It is absent from
  provider, verification, and diagnostic children and never appears in command arguments.
- Made the long-lived Factory process non-dumpable after discovering that removing a token from `os.environ`
  does not erase the original value exposed by `/proc/<pid>/environ`.
- Put every direct provider in private user, mount, PID, and proc namespaces. Only its worktree, a read-only base
  checkout, provider-owned credential paths, and read-only runtime paths are restored after hiding every other
  provider session, durable state, logs, runtime sockets, and host temporary files.
- Put repository-controlled verification in a stricter no-network namespace with fresh home and temporary
  storage, read-only shared dependencies, and no access to provider sessions or Factory state.
- Restricted GitHub CLI children to an explicit runtime allowlist plus the scoped repository token instead of
  inheriting unrelated daemon, database, and provider secrets.
- Removed bootstrap's dependency on service-user `gh auth` state. Setup and deployment now read the token from
  root-only configuration while the daemon is stopped, reset inherited credential helpers, and scope the token
  to each clone, fetch, or fast-forward child.
- Made doctor reject readable GitHub CLI OAuth state, persistent Git credential files, an unreset helper chain,
  unavailable provider namespaces, or unavailable verification isolation.
- Added a deterministic diff gate for provider credential directories, high-confidence access tokens, and private
  keys. Evidence is redacted before it can enter durable state or logs.
- Ran every direct provider health probe in a disposable empty workspace which is removed after the probe.
- Removed GitHub, Telegram, and legacy Gemini credentials from the configuration serialised into the OpenHands
  child while retaining only the selected execution-provider settings.
- Removed the autonomous meta-agent and its systemd unit.

### Operations

- Made deployment source `origin/main` only and fast-forward the dedicated checkout.
- Made deployment refresh the frozen Python environment, every shared Node dependency tree, Cypress, and the
  secretless worker image from the same `origin/main` revision.
- Preserved operator `agents.json` while publishing the current default as `agents.example.json`.
- Removed hard-coded service UIDs and generated `/etc/hellotalk-factory/runtime.env` from the installed user.
- Enabled linger and the matching user systemd session for rootless Podman.
- Retired old meta-agent units during setup, repair, deployment, and startup.
- Extended doctor with provider installation, auth, model, transport, capacity, aggregate usability, the Git
  credential helper, and authenticated read access to the configured GitHub repository.
- Added a bounded systemd preflight which requires single runtime ownership, repository access, and a no-bypass
  merge ruleset without making temporary aggregate provider exhaustion or one optional OpenAI OAuth path fatal.
  Zero usable providers is an explicit warning, leaving durable work online for health recovery.
- Added queue ordering for guardian, critical, high, medium, ordinary, and low-priority work.
- Made quarantine recovery restore the configured intake-ready label when labelled intake is required.
- Connected `FACTORY_MAX_CONSECUTIVE_FAILURES` to durable identical-failure fingerprints so deterministic
  task-side failures open a recoverable circuit instead of retrying forever. Provider exhaustion remains exempt,
  and the backlog command now reconciles durable state with GitHub labels idempotently.
- Updated the dated OpenCode policy to use Kimi K3 for implementation and repair, Qwen3.8 Max for independent
  reasoning and review, and Kimi K2.7 Code for high-capacity mechanical actions.

### Known source-level limitations

- Direct CLI credential isolation depends on the operator-maintained relative path lists matching each installed
  vendor release. Paths are provider-specific, but a moved or newly added credential file requires an explicit
  configuration update and canary.
- OpenHands is one outer adapter but can internally select OpenAI subscription OAuth or a configured OpenCode API
  profile. Outer job history records `openhands-sdk`; detailed inner attribution is stored separately.
- Budget configuration is not exact cross-vendor metering and does not prove a hard PAYG cap.
- CI repair receives failed check names and mergeability, not a redacted log excerpt.
- Google is disabled in the production-safe initial policy pending a service-user canary.
- Cross-repository PRs are intentionally excluded until a read-only review path exists; the Factory cannot repair
  a fork branch it cannot push.
- Provider performance counters exist, but adaptive scoring and model promotion remain future work.
- Required status names are checked, but their publisher identity is not yet attested or validated by doctor.
- Direct providers can read their own subscription sessions and need vendor network access. Trusted intake limits
  exposure, but domain-restricted egress or a broker would provide a stronger boundary.

## Definition of autonomous

The Factory is autonomous when it can continuously discover eligible work, recover after daemon restart, route
around provider-side failures, preserve task state when no provider is available, verify and independently review
every change, repair attributable failures, and merge only the currently reviewed commit.

It must still stop unsafe task or merge progress for expired human credentials, ambiguous product decisions,
repository policy failures, unavailable GitHub infrastructure, or zero usable providers. The daemon and durable
queue remain online so recoverable conditions can clear. Silently bypassing those conditions would be less
autonomous in the engineering sense because it would sacrifice recoverability and correctness for activity.
